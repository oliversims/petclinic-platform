# ADR-0011: AWS Secrets Manager for secret storage

**Status:** Accepted
**Date:** 2026-09-02

## Context
The platform holds two secrets: the RDS master credentials and an OpenAI API key. They
must reach pods as environment variables without ever appearing in Git.

The options are AWS Secrets Manager, SSM Parameter Store SecureString, or Kubernetes
Secrets committed with something like Sealed Secrets.

## Decision
AWS Secrets Manager as the source of truth, with External Secrets Operator syncing values
into Kubernetes Secrets.

- Secrets are named `petclinic/{env}/rds-credentials` and `petclinic/{env}/openai-api-key`.
- The RDS password is generated by Terraform `random_password`, never typed by a person.
- ESO reads them through an IRSA role scoped to `petclinic/*` and refreshes hourly.
- `ExternalSecret` CRs in `k8s/base/external-secrets/` reference secrets; they contain no
  values.
- Rotation is manual — there is no `aws_secretsmanager_secret_rotation` resource. See
  [secret-rotation.md](../secret-rotation.md).

## Consequences
**Positive**

- No secret material in Git, in a Helm value, or in a container image.
- Fine-grained IAM: the ESO role can read `petclinic/*` and nothing else.
- Encrypted at rest with the AWS-managed KMS key; versioned, so a bad rotation can be
  rolled back by moving the `AWSCURRENT` stage.
- Built-in rotation capability is available later without changing the storage layer.

**Negative**

- About $0.40 per secret per month — more than Parameter Store, which is free at standard
  tier. Roughly $1.20/month total here.
- Values still land in Terraform state in cleartext, because `random_password` generates
  them; access to the state bucket is therefore equivalent to credential access.
- ESO is another controller to install, upgrade, and monitor.
- A one-hour refresh means a rotated secret is not instant, and pods must be restarted to
  pick up new environment variables.
